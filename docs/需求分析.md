# OPP 需求分析

> 状态：持续整理  
> 对应版本：v0.2.3  
> 最近更新：2026-07-25

## 1. 产品定位

OPP 面向 osu! 玩家，目标是将个人资料、本地谱面、Skin、实用工具和内容创作能力整合到一个桌面工作台中。

产品应长期遵循以下原则：

1. **本地优先**：本地资源默认只读，任何写入操作都必须可预览、可撤销并由用户确认。
2. **来源透明**：明确区分 osu!stable、osu!lazer、官方 API 与第三方数据。
3. **渐进增强**：Lazer Realm、资源修改、Replay 等高风险能力通过独立适配器逐步加入。
4. **可验证**：分析结果需要结构化诊断、自动化测试和真实目录比对。
5. **不伪造完整度**：无法确认的资源关系必须标记为部分或未知。

## 2. 当前已实现：v0.2.3

### 用户与在线资料

- osu! API v2 OAuth 登录。
- 四模式个人资料、统计与排名。
- Top 100 最佳成绩浏览。
- Windows 凭据管理器保存 OAuth 密钥与 Token。

### 本地谱面

- 自动检测与手动配置 Stable / Lazer 数据源。
- `.osu` 元数据、结构、NPS、NoMod 星数、最大连击与 strain 分析。
- 按 BeatmapSet 聚合难度。
- 多条件搜索、筛选、排序和分页。
- Stable 本地背景缩略图。
- 增量索引、取消扫描、强制重建与结构化诊断。

### 本地 Skin

- `skin.ini` 配置、颜色、重复键和 Mania Section 解析。
- Stable 资源数量、体积与扩展名统计。
- Skin 图片分页预览。
- WAV、MP3、OGG 音效试听。
- 不透明资源 ID 和媒体载荷接口。
- Lazer legacy 配置候选识别，但不读取 Realm 或伪造资源归属。

## 4. 重点功能分析

### 4.1 Skin 可视化编辑

v0.2.3 已经具备资源枚举、图片预览、音效试听和不透明资源 ID，可在此基础上增加：

1. 选择图片或音效资源。
2. 查看原始资源和待替换资源的差异。
3. 在临时工作区生成修改方案。
4. 显示将要新增、覆盖或删除的文件。
5. 创建完整备份后执行原子替换。
6. 支持撤销并重新扫描索引。

首版不应直接编辑原始文件，也不应处理 Lazer Realm 内无法确认归属的资源。

### 4.2 谱面镜像下载

这是高依赖功能，进入开发前需要回答：

- 数据来自官方 API、Mapper 提供的链接还是第三方镜像？
- 下载源是否允许自动化访问和二次分发？
- 如何校验谱面集 ID、文件哈希与归档完整性？
- 是否允许下载 DMCA、墓地或未提交内容？
- 下载后如何避免覆盖用户现有谱面？

在数据源和合规边界明确前，不进入实现阶段。

### 4.3 关联网易云音乐

可能的用户价值是查找谱面歌曲、补充元数据或跳转播放。需要先确认：

- 使用官方开放能力、网页搜索还是仅生成搜索关键词？
- 是否涉及音频下载、缓存或版权内容？
- 标题、艺术家、版本和音源不一致时如何匹配？

建议首版只提供“生成搜索链接”，不下载或代理音频。

### 4.4 Mania 工具链

所有谱面转换工具应共用一个不可变工作流：

```text
读取原谱面 → 生成转换计划 → 展示差异 → 导出到新文件 → 重新解析验证
```

转换必须保留原谱面，不允许静默覆盖。倍速功能还需要同步处理 timing、物件、break、预览点和音频策略。

### 4.5 Replay 与视频

Replay 视频生成至少包含：

- Replay 解析与时间轴校准。
- Ruleset 对应的游戏画面渲染。
- Skin、谱面背景和音频资源装配。
- 视频编码、分辨率、帧率与硬件加速。
- 成绩信息、玩家隐私和版权素材处理。

建议先实现 Replay 数据检查器，再评估完整视频渲染。

## 5. 下一阶段建议：v0.3

建议将 v0.3 聚焦在 Skin 工作流，避免同时展开社交、Replay 和第三方下载：

1. Skin 资源搜索、类型与用途分类。
2. 单资源替换预览。
3. 修改计划与差异视图。
4. 备份、原子写入与撤销。
5. 导出为新 Skin 文件夹或 `.osk`。
6. Stable 真实目录验收与损坏资源恢复测试。

## 6. 待确认问题

- 项目是公开源码、仅公开 Release，还是允许社区贡献？
- 计划采用哪一种开源许可证？
- “完整用户数据”具体包含哪些 osu! API 字段？
- Rework Queue 的对象是谱面、Skin、成绩图任务还是通用工作项？
- Mania 段位数据来自哪个规则体系？
- “OSU alpha”和“roma AI”分别指什么功能？
- 第三方谱面和音乐服务允许使用哪些数据源？

## 7. 非目标

在需求和安全设计完成前，以下内容不作为默认能力：

- 修改 `client.realm`。
- 静默覆盖用户的谱面、Skin 或回放。
- 绕过第三方服务授权、下载限制或版权保护。
- 未经确认上传本地 osu! 文件、Token 或用户隐私数据。
- 将推断结果展示为官方或完整数据。
