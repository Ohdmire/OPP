# OPP 项目快速入门

这是一份给新贡献者与编码助手共用的导航文档。目标是让你在不通读整个仓库的情况下，找到运行入口、功能边界和安全约束。

## 0. Rust 后端导览（2026-07 重构后）

后端按“领域优先”组织。`src-tauri/src/lib.rs` 只负责创建 `AppState`、安装插件和注册 Tauri 命令；它不再承载具体业务。新增或修改功能时，请先进入对应领域目录，再沿着“命令入口 → 服务/逻辑 → 模型或外部适配器”的方向阅读。

```text
前端 invoke
    │
    ├── account/             OAuth、凭据、令牌刷新、个人资料与设置
    ├── local_analysis/      本地 osu! 资源发现、扫描、索引与查询
    ├── online_beatmaps/     官方搜索、镜像供应商、下载与进度事件
    ├── similarity/          Analyzer v3 数据集、相似查询与成绩推荐
    ├── game_session/        启动会话、媒体访问与回放元数据
    ├── replay_render/       o!rdr 提交、选项校验与进度事件
    ├── netease_music.rs     网易云音乐搜索与客户端唤起
    ├── trainer.rs           Trainer 练习谱面生成
    └── pp_calc.rs           纯 PP 计算命令
```

| 位置 | 作用 | 修改时的注意点 |
| --- | --- | --- |
| `account/mod.rs` | 账户领域对外导出 | 新命令在此导出，再在 `lib.rs` 注册。 |
| `account/token.rs` | 唯一的访问令牌刷新入口 | 其他领域只调用 `ensure_access_token`，不要自行刷新或读写 Token。 |
| `online_beatmaps/providers.rs` | Nerinyan/Catboy 第三方适配器 | 供应商失败须转换为 `CommandError`，不可把网络细节泄漏到前端。 |
| `game_session/models.rs` | 游戏会话与媒体的跨端数据结构 | 字段名是前端契约；改动须同步对应的前端调用页面。 |
| `replay_render/events.rs` | 回放渲染进度事件负载 | 事件名 `ordr-render-progress` 与字段应保持向后兼容。 |
| `state.rs` | 应用共享依赖与运行时状态 | 只注入领域服务，不在这里增加业务流程。 |

### 增加一个后端能力

1. 选择已有领域；只有真正跨领域的稳定能力才新建目录。
2. 在领域的 `models.rs`（或就近模型模块）定义输入/输出；先保证 serde 字段名与前端一致。
3. 将文件系统、网络或计算逻辑放入命名明确、可单测的函数；`#[tauri::command]` 仅负责参数、状态和调用编排。
4. 从领域的 `mod.rs` 导出命令，并在 `src-tauri/src/lib.rs` 的 `generate_handler!` 中注册。
5. 在 `src/shared/lib/tauri.ts` 增加类型化桥接，避免页面直接调用 `invoke`。
6. 至少运行 `cargo fmt --check`、`cargo clippy -- -D warnings` 和 `cargo test`。

## 1. 项目是什么

OPP 是一个 Windows 桌面端 osu! 工具集合：React 负责界面，Tauri 负责桌面桥接，Rust 负责 OAuth、本地资源分析、网络请求和文件系统操作。

```text
浏览器界面 (src/) ── Tauri invoke ── Rust 命令 (src-tauri/src/) ── osu! API / 本地文件
```

本项目仅分析用户明确选择或客户端默认目录中的本地资源。不要把 OAuth 密钥、访问令牌、用户游戏资源或应用数据目录提交到仓库。

## 2. 首次运行

### 必要环境

- Windows 10/11 与 Microsoft Edge WebView2 Runtime
- Node.js 22+、pnpm 11+
- Rust stable（MSVC toolchain）与 Windows SDK

### 开发模式

```powershell
pnpm install
pnpm tauri dev
```

第一次使用在线功能时，需要在 osu! 账户设置中创建仅供个人使用的 OAuth 应用，并将回调地址设为：

```text
http://127.0.0.1:42831/oauth/callback
```

不要分享或提交 Client Secret、Token 或 Windows 凭据导出文件。

## 3. 代码地图

| 位置 | 职责 | 从这里开始的时机 |
| --- | --- | --- |
| `src/main.tsx` | React 挂载入口 | 排查前端启动问题 |
| `src/App.tsx` | 全局 Provider、路由器和标题栏组合 | 调整应用最外层结构 |
| `src/app/AppConnectionGate.tsx` | 登录状态、设置加载与已连接应用的入口 | 修改鉴权前后的体验 |
| `src/app/AppRoutes.tsx` | 功能页面路由与按路由懒加载 | 新增页面或修改导航路径 |
| `src/features/<feature>/` | 按业务领域组织的 UI、查询和 API 适配 | 开发具体功能 |
| `src/shared/` | 跨功能复用的类型、组件、格式化和 Tauri 调用 | 提炼稳定的公共能力 |
| `src-tauri/src/lib.rs` | Tauri 命令注册、依赖装配与应用启动 | 注册已由领域 `mod.rs` 导出的命令；不在此实现业务逻辑 |
| `src-tauri/src/account/` | OAuth、凭据、令牌生命周期、资料缓存和设置 | 登录、Token 刷新、个人资料或设置功能 |
| `src-tauri/src/online_beatmaps/` | 在线搜索、供应商适配、批量下载和进度事件 | 在线谱面查询、镜像下载或供应商接入 |
| `src-tauri/src/similarity/` | Analyzer v3 数据集读取、相似查询和成绩推荐 | 修改相似度权重、过滤或推荐逻辑 |
| `src-tauri/src/game_session/` | 游戏进程会话与本地媒体访问 | 启动游戏、读取回放或截图 |
| `src-tauri/src/replay_render/` | o!rdr 提交与渲染进度 | 回放渲染参数、队列和事件 |
| `src-tauri/src/local_analysis/` | 本地 osu! 目录发现、扫描、缓存和查询 | 本地谱面/Skin 功能 |
| `src-tauri/src/local_analysis/service_data.rs` | 本地分析缓存模型与可靠落盘 | 修改索引格式或缓存策略 |
| `src-tauri/src/local_analysis/service_query.rs` | 本地索引的过滤、排序、分页与资源枚举 | 修改列表查询规则 |

## 4. 一次功能改动的推荐路径

1. 在 `src/shared/types/osu.ts` 定义跨端数据结构；字段使用现有的 `snake_case` 风格，以匹配 Rust 序列化结果。
2. 在对应的 Rust 领域模块实现 `#[tauri::command]`，并在 `src-tauri/src/lib.rs` 注册。
3. 在 `src/shared/lib/tauri.ts` 添加类型化的 `desktopApi` 方法；不要在页面里直接调用 `invoke`。
4. 在 `src/features/` 中实现页面、面板和 React Query 调用；只有可复用组件才放入 `src/shared/components/`。
5. 为纯逻辑补单元测试；涉及本地路径时覆盖无效路径、越界路径和超大文件。

## 5. 本地分析模块的工作方式

本地分析以“发现 → 索引 → 查询 → 按需预览”组织：

1. `sources.rs` 确定 stable/lazer 数据源，并校验目录。
2. `service.rs` 协调扫描任务、进度、取消与内存索引。
3. `service_data.rs` 定义持久化索引，并以“临时文件 → 备份 → 替换”保护缓存写入。
4. `parser.rs` 识别和解析谱面、Skin 配置，计算需要的统计数据。
5. `service_query.rs` 从已验证的索引中筛选、排序、分页，并枚举可预览的 Skin 资源。

重要约束：所有来自本地目录的资源路径都必须在使用前规范化并确认仍位于允许根目录内；预览必须保留大小、尺寸和格式限制。

## 6. 验证命令

完成改动后，按影响范围运行相应检查：

```powershell
pnpm lint
pnpm test
pnpm build

cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml
```

完整桌面打包使用 `pnpm tauri build`。生成的 NSIS 安装包位于 `src-tauri/target/release/bundle/nsis/`。

## 7. 给 AI 的执行约定

- 先阅读目标功能目录、共享类型和对应 Rust 命令，再修改代码；避免同一能力出现两套数据模型或两条调用链。
- 页面保持“组装”职责。复杂筛选、格式化或文件处理应放入命名明确、可测试的函数/模块。
- 修改 Tauri 命令时，前后端类型与参数名必须同步更新。
- 保持用户已有的未提交改动；不要用重置、强制覆盖或批量删除来“清理”工作区。
- 优先补充解释设计约束的注释，而不是复述语法本身的注释。

## 8. 常见入口

- 新工具页：参考 `src/features/tools/ToolsPage.tsx`，然后在 `AppRoutes.tsx` 与侧栏注册。
- 新本地资源能力：从 `src-tauri/src/local_analysis/mod.rs` 的命令层和 `src/shared/lib/tauri.ts` 的桥接层同时开始。
- 修改游戏会话：查看 `src/features/game/` 与 `src-tauri/src/game_session/`。
- 调整 OAuth 或个人资料请求：查看 `src/features/auth/`、`src-tauri/src/account/` 和 `src-tauri/src/osu_api.rs`。
